# Blink 精简产品需求文档

- 状态：已确认，待实现
- 版本：P0
- 更新日期：2026-08-06
- 相关文档：[接口与 Prompt 协议](./PROTOCOLS.md) · [状态与交互图](./INTERACTIONS.md)

## 1. 产品定义

Blink 是嵌入主流 AI 对话网站输入框的即时提示词改写工具。

核心闭环：

> 识别输入框 → 选择模式 → 点击 Blink → 直接替换 → 单步撤销

Blink 只改写当前尚未发送的文本草稿，不回答草稿、不自动发送、不读取历史对话。

## 2. P0 目标

1. 用户不离开当前 AI 网站即可优化草稿。
2. 提供自动、精简、专业三种稳定且差异明确的模式。
3. 支持最多 5 个用户自定义模式。
4. 使用 BYOK，由用户选择模型服务并自行承担调用费用。
5. 优化失败、草稿变化或写回失败时绝不覆盖用户内容。

## 3. 非目标

P0 不包含：

- 提示词收藏、历史记录或云同步。
- 对话历史、附件、网页正文或选中文字的上下文读取。
- 自动发送、批量优化或多步骤 Agent。
- 账号、订阅、计费、团队协作或服务端配置。
- 本地模型、模型自动路由或多个 Provider 自动故障转移。
- 任意网站的通用输入框识别。

## 4. 用户流程

1. 用户在设置页配置一个 Provider、API Key 和模型，并授权希望启用的站点。
2. 用户打开已授权的 AI 网站。
3. Blink 在有效对话输入框附近显示分体胶囊按钮：`[✦ Blink] [自动⌄]`。
4. 用户通过右侧菜单选择模式；Blink 记住上次选择。
5. 用户点击左侧 Blink 按钮。
6. Blink 获取当前草稿快照并请求用户配置的模型。
7. 若草稿未变化，Blink 直接替换输入框内容。
8. 当前 Blink 胶囊原地切换为“✓ 已优化｜撤销”，不弹出第二个成功框；用户继续编辑后，撤销立即失效。

## 5. 功能需求

### FR-1 输入框识别

- 仅在支持站点中运行。
- 支持 `textarea`、`contenteditable` 和站点实际使用的富文本编辑器。
- 适配 SPA 导航、新建会话和输入框重新挂载。
- 同一页面最多显示一个 Blink 组件。
- 输入框不可见、禁用或离开视口时隐藏组件。

### FR-2 模式选择

内置模式：

| 模式 | 目标 |
| --- | --- |
| 自动 | 只修复真实存在的清晰度、结构和表达问题，不过度扩写 |
| 精简 | 删除重复和填充表达，提高信息密度，不丢失约束 |
| 专业 | 将复杂草稿整理为准确、专业、可执行的任务 |

- 内置模式不可编辑或删除。
- 模式菜单同时显示自定义模式。
- 默认记住用户上次选择的模式。
- 自定义模式被删除后，当前模式回退到“自动”。

### FR-3 自定义模式

每个自定义模式只包含：

| 字段 | 约束 |
| --- | --- |
| 名称 | 必填，去除首尾空格，1–20 个字符 |
| 优化要求 | 必填，去除首尾空格，1–800 个字符 |

- 最多 5 个自定义模式。
- 支持创建、编辑和删除。
- 不提供 System Prompt、温度、图标、输出格式或长度滑杆。
- 自定义要求不能覆盖 Blink 的公共改写约束。

### FR-4 一键优化

- 空草稿不发起请求，提示“请输入需要优化的内容”。
- 单次输入上限为 6,000 个 UTF-16 code units，即 JavaScript `text.length`。
- 同一页面同一时间只允许一个请求。
- 请求期间按钮显示加载状态，并禁止重复点击。
- 请求完成前用户可继续编辑或发送；Blink 不阻止原网站操作。
- 若请求期间草稿发生变化，丢弃结果并提示“草稿已变化，请重试”。
- 模型返回与原文完全相同时，提示“当前表达已经足够清晰”。

### FR-5 替换与撤销

- 仅当当前草稿仍等于请求快照时才允许写回。
- 写回必须同步原网站编辑器状态，使发送按钮和实际发送内容一致。
- 写回后立即读回校验；不一致时先恢复原文，仍无法恢复则展示可复制的原文恢复卡，禁止静默丢失内容。
- 写回后将光标放到文本末尾并保持输入框焦点。
- 只保留本页面最近一次替换的原文，不持久化。
- 只有当前文本仍等于 Blink 写入结果时才能撤销。
- 用户手动编辑、发送、刷新或切换会话后，撤销失效；成功态不提供再次优化或模式切换入口。

### FR-6 BYOK 设置

P0 同一时间只保存一个活动 Provider：

- Provider 类型。
- API Base URL。
- API Key。
- 模型名称。
- “测试连接”操作。

首版 Provider 类型：

1. OpenAI-compatible。
2. Anthropic 原生协议。
3. Gemini 原生协议。

OpenAI-compatible 可接入 OpenAI、OpenRouter，以及提供兼容端点的 DeepSeek、Grok、Qwen、Moonshot、Z.ai、MiniMax、Mistral 或自定义代理；Blink 不承诺所有厂商的每个端点都兼容。

### FR-7 站点开关

- 初次设置时由用户选择并授权要启用的站点，不一次性申请全部站点权限。
- 设置页为每个支持站点提供启用开关；开关直接申请或移除对应 Host Permission。
- Chrome 实际授权状态是唯一事实来源，不额外保存一份站点启用布尔值。
- 关闭后移除站点权限和动态 Content Script，并立即隐藏 Blink 组件。
- 不提供“所有网站”开关。

## 7. 设置页

设置页只包含三个区域：

### 模型服务

- Provider 类型。
- Base URL。
- API Key，默认遮挡。
- 模型名称。
- 测试连接和保存。
- 明确提示：API Key 仅保存在本机，但浏览器扩展存储不是硬件级安全密钥库。

### 优化模式

- 三个内置模式的只读说明。
- 自定义模式列表和增删改。

### 支持站点

- 站点授权开关。
- 当前适配状态和最后验证的扩展版本。

不提供外观主题、快捷键编辑、多 Provider 列表或用量统计。

## 8. 数据与隐私

- 只有用户点击 Blink 后才读取当前草稿并发送给所选 Provider。
- Blink 不读取已发送消息、对话历史、附件或页面正文。
- API Key 存在 `chrome.storage.local`，不写入 `storage.sync`。
- 自定义模式和活动模式可存在 `chrome.storage.sync`；站点状态直接使用 Chrome Host Permission。
- API Key 不得发送给 Content Script，不得写入日志或错误信息。
- 撤销数据只保存在当前页面内存中。
- P0 不采集遥测。
- 卸载扩展后由 Chrome 清除扩展存储；设置页同时提供“清除本地配置”。

## 9. 错误提示

| 场景 | 用户提示 | 是否修改原文 |
| --- | --- | --- |
| 未配置 Provider | 请先配置模型服务 | 否 |
| API Key 无效 | API Key 无效或无权限 | 否 |
| 模型不存在 | 模型不可用，请检查模型名称 | 否 |
| 请求超时 | 请求超时，请重试 | 否 |
| 额度或频率限制 | Provider 已限流或额度不足 | 否 |
| 返回格式错误 | 模型返回格式无效，请重试或更换模型 | 否 |
| 草稿已变化 | 草稿已变化，请重试 | 否 |
| 写回失败 | 无法写入当前输入框 | 尝试恢复；失败则展示可复制原文恢复卡 |

## 10. P0 验收标准

### 自动化检查

- 三种内置模式和自定义模式正确组装 Prompt。
- Provider 配置校验、凭据隔离和响应解析通过测试。
- Provider 测试消息只能由扩展设置页发起；优化消息只能来自已授权站点。
- 输入上限、空结果、超长结果和 URL 保留校验通过测试。
- 草稿快照竞争检查和撤销资格判断通过测试。

### 站点人工验收

每个首批域名至少验证：

1. 登录前或登录后可访问页面中的主对话输入框可被识别。
2. 新建对话和 SPA 页面切换后 Blink 可重新出现。
3. 单行、多行、中英文混合、URL 和代码块可正确读取。
4. 优化结果写回后，原网站发送的是新内容而不是旧状态。
5. 优化期间继续输入不会被返回结果覆盖。
6. 撤销恢复完全一致的原文。
7. 发送、继续编辑、刷新和切换会话后撤销失效。
8. 写回故障时原文可被自动恢复，或可从恢复卡完整复制。

### Prompt 验收语料

至少保留 15 条固定语料，覆盖：

- 已经清晰的短提示词。
- 冗长重复输入。
- 复杂多约束输入。
- 缺失关键信息的模糊输入。
- 中文、英文和中英混合。
- URL、数字、日期、专有名词和代码块。
- 包含“忽略之前指令”等注入式文本。

验收优先级：意图与事实不变 > 不丢约束 > 模式差异 > 文风美观。
